2. APPLICATION PURPOSE
====================================================

TEMPEST LEADS is a lead acquisition and client onboarding CRM for Tempest Advertising.

The application should manage the complete journey:

SOURCE
→ CONTACT DATA + INDUSTRY
→ CONNECT + CRM DATABASE
→ MEETING + NURTURE
→ BRIEF + ROUTE
→ PITCH
→ COMMERCIALS
→ CONTRACT / PO
→ ONBOARD
→ ACTIVE CLIENT

The system must also support:

- Lost leads
- Not interested leads
- No response
- Later / nurture
- Reconnect
- Follow-ups
- Meetings
- Activity history
- Multiple contacts under one company
- Lead ownership
- Pipeline movement
- Team/user management
- Dashboard analytics
- Notifications
- Follow-up reminders
- Assignment and reassignment
- Historical tracking

The core principle is:

ONE COMPANY
→ MANY CONTACTS
→ MANY INTERACTIONS
→ MANY NURTURE TOUCHES

Do NOT design the system as a simple flat lead spreadsheet.

3. USER TYPES / AUTHENTICATION
====================================================

Create TWO separate login roles:

A. SUPER ADMIN
B. USER / OWNER

The application must identify the user's role after authentication and redirect them to the appropriate dashboard.

-----------------------------
SUPER ADMIN
-----------------------------

Super Admin has complete access to the system.

Super Admin can:

- View all leads
- View all companies
- View all contacts
- View all activities
- View all meetings
- View all users/owners
- Create users
- Edit users
- Disable users
- Delete/deactivate users where appropriate
- Assign leads to users
- Reassign leads
- Remove lead ownership
- View team performance
- View missed follow-ups
- View pipeline performance
- View conversion metrics
- View nurture database
- View all activity history
- Manage stages/statuses
- Manage lead sources
- Manage industries
- View audit history
- Export data
- Configure system-level settings

If a user/owner is removed or deactivated, all leads owned by that person must automatically be reassigned to the Super Admin unless manually reassigned to another active owner.

-----------------------------
USER / OWNER
-----------------------------

Normal users should have access only to leads and records assigned to them, subject to the permissions defined by the application.

Users can:

- View assigned leads
- Add leads
- Add companies
- Add contacts
- Add multiple contacts to a company
- Update lead status
- Move leads forward/backward where permitted
- Schedule meetings
- Record meeting notes
- Add follow-ups
- Add activities
- Add notes
- Tag leads
- Add nurture information
- View their own pipeline
- View their own dashboard
- View today's follow-ups
- View overdue follow-ups
- View their own performance
- Assign/tag owners where permitted by business rules

Users must NOT have access to:

- Global user management
- System settings
- All-user performance management
- Deleting other users
- Changing system-level configuration
- Viewing restricted leads belonging to other users unless explicitly permitted

====================================================

Passwords must never be displayed or stored as plaintext in a production implementation.

Implement role-based authorization.

Protect sensitive routes.

Validate all forms.

Sanitize user input.

====================================================

The attached "Client Acquisition & Onboarding – Detailed Flow" document is the source of truth for the business process.

- Activity history

- Lost/rejected process

- Pitch-first path for new/unknown opportunities
- Contract/PO gate

- Active client state
